## Phase 6 — Live Experiment Assignment & Outcome Observation

- `backend/engine/phase6_config.py` - Phase 6 declared bounds, committed at checkpoint X0 before `assign_experiment_group.py` existed and before a single opportunity had been assigned. The assignment method (blake2b hash bucketing over salt + opportunity_id, ruling R2 over R4), `HOLDOUT_FRACTION=0.5`, `SUPPRESSION_OUTCOME='suppressed_holdout'`, `UNASSIGNED_IS_SUPPRESSED=False` (the project's one deliberate fail-open, dated), and the full randomization-balance gate: `MAX_ABS_SMD=0.10`, `MIN_ASSIGNED_N=3500`, the covariate list, the degenerate-SMD conventions and the holdout-aware eligibility floor. `MIN_ASSIGNED_N` carries a dated amendment (200 → 3500 at X5) with the power curve that justifies it; `MAX_ABS_SMD` has never been changed.
- `backend/engine/assign_experiment_group.py` - randomized assignment at opportunity-creation time. Zero execution authority; its only write is `INSERT INTO experiment_assignment`. Idempotent on the primary key, with an `IntegrityError` handler that distinguishes the PK race (return the row that won) from a FK miss (assign nothing). The randomness itself is not here — it is `phase6_config.assigned_group()`, a pure function of the id and the locked salt, so any row's arm is independently recomputable.
- `backend/engine/observe_outcome.py` - **the single path by which any business outcome reaches an opportunity**, whatever the source. Closed vocabularies for `resolution` and `source`, both required and keyword-only. Carries the compare-and-swap adopted unchanged from `mark_opportunity_recovered()`; deliberately NOT experiment-aware, enforced by a static gate, because an outcome writer that consulted `experiment_assignment` could suppress control recoveries and make the experiment circular.
- `backend/analytics/randomization_balance.py` - the balance report. `balance_report()` computes raw figures (per-arm n, distribution summaries, the full level × arm contingency table, every signed SMD); `verdict()` derives PASS/FAIL/NOT_EVALUABLE from them against the locked bounds. Deliberately two functions so a gate reports numbers rather than a verdict.
- `backend/analytics/counterfactual_consistency.py` - the suppression report. Four violation probes bounded at `assigned_at`, run against **both** arms: control must be zero, treatment must be non-zero, because "control shows nothing" is unfalsifiable on its own — a system acting on nobody would pass a control-only check.
- `backend/analytics/balance_power_analysis.py` - how large the assigned population must be for the balance gate to mean anything. `power_curve()` measures the false-failure rate under the true-random null (the real locked hash, seeded and reproducible); `detection_curve()` measures the opposite, reported against the imbalance each bias actually induces rather than against the raw bias knob. Written because the gate failed at n=240 and the failure turned out to carry no information about the randomizer.
- `backend/data/generate_experiment_volume.py` - creates assignment volume through the real `trigger_event()` path, so the gates run against a population the system actually assigned. Event mix is seed-reproducible; the arm assignment is not, by design.
- `backend/tests/test_phase6_config.py` - config and lock file agree on every shared number, each ruling is pinned, and the bucketing is deterministic, salt-dependent and uniform.
- `backend/tests/test_phase6_assignment.py` - assignment happens once and only once, precedes the first decision, survives a replayed event, and reaches both arms through real `trigger_event` ids.
- `backend/tests/test_phase6_suppression.py` - control suppression: the verdict, its precedence over every terminal branch, the dispatcher path, the optimizer half, and an AST test asserting the gate is structurally first in `decide_action()`.
- `backend/tests/test_phase6_outcome.py` - the single ingestion path: vocabularies, each resolution's row shape, terminal-state protection, every source routing through, and the stop-cannot-overwrite-a-recovery case that motivated unification.
- `backend/tests/test_phase6_gates.py` - the two hard gates. The balance gate carries `@pytest.mark.slow` (opt in with `-m slow`, ~77 s); the counterfactual gate runs every time. Includes the negative controls that make each falsifiable.

## Phase 6 exit gate + Phase 7 — Live Incremental Attribution

- `backend/data/generate_experiment_outcomes.py` - realizes a SYNTHETIC business outcome for every assigned opportunity through `observe_outcome()`, the single ingestion path. Treatment realizes the candidate the rule engine actually selected; control realizes `do_nothing`. Hidden state is sampled once per opportunity, seeded from the opportunity_id and independent of the arm — if it depended on the arm, the measured difference would include one this generator invented. Records `outcome_source='synthetic_potential_outcome'`.
- `backend/analytics/incremental_attribution.py` - the aggregate incremental figure. Difference in proportions (Wald 95% CI) for the rate, difference in means (Welch, unpooled) for rupees. `MIN_N_PER_ARM = 30` is a permanent refusal gate returning "insufficient data" and no number. Publishes its own SQL via `sql_trace()`, caches nothing, refuses outright on a population mixing synthetic and confirmed outcome sources, and emits BOTH denominators for the predicted-vs-observed diagnostic so the two figures cannot be compared across mismatched populations. **Aggregate scope only — segmentation is cut and disclosed.**
- `backend/tests/test_phase6_exit_gate.py` - the acceptance-gate rows Phase 6's own DoD did not name: concurrent assignment safety at the application layer, `[NEW]` duplicate-outcome safety in three forms (repeat, conflicting, concurrent), no-retroactive-contamination, lineage from outcome back through decision and execution, and the end-to-end controlled experiment.
